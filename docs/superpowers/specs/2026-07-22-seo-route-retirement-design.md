# SEO Structured Data and Template Route Retirement Design

## Goal

Keep the existing valid server-rendered JSON-LD and permanently retire the
unused TanStarter template pages without shipping their route bundles.

## Confirmed Behavior

- The home page server response contains valid `WebSite` and `FAQPage` JSON-LD.
- `/challenge` contains valid `FAQPage` JSON-LD.
- Client-side hydration may display managed script tags as empty in the live
  DOM. This does not remove JSON-LD from the original SSR response.
- The site has not launched, but the retired paths will return permanent
  redirects so any early links have deterministic behavior.

## Retired Paths

- `/about`
- `/ai`
- `/contact`
- `/roadmap`
- `/waitlist`

Each exact path, including a query string, redirects with HTTP 301 to the site
root while preserving the request origin. Subpaths such as `/about/team` are
not matched and continue to the normal 404 handler.

## Architecture

The five route files are deleted so TanStack route generation removes them and
their page imports from the production route graph. A small pure helper in
`src/lib/retired-template-route.ts` recognizes only the five exact paths and
returns the root URL. `src/server.ts` calls it before locale middleware and
returns `Response.redirect(target, 301)`.

The related starter components and translation messages remain in the source
tree. Removing them is outside this change and is unnecessary once no route
imports them.

The matching entries are removed from `src/lib/routes.ts` and the localized
path allowlist in `src/lib/locale.ts`. `src/routeTree.gen.ts` is regenerated by
the normal TanStack/Vite workflow and is never edited manually.

## D1 Configuration Boundary

- Cloudflare Worker runtime continues to use the `DB` binding and database ID
  resolved by Wrangler from the database name declared in `wrangler.jsonc`.
- Local remote-Drizzle commands read `CLOUDFLARE_DATABASE_ID` from the ignored
  `.env` file. The local value is never committed.
- `.env.example` keeps an empty `CLOUDFLARE_DATABASE_ID` as documentation.
- GitHub Actions uses the repository secret named
  `CLOUDFLARE_DATABASE_ID`. Secret creation is an external repository setting,
  not a committed file change.

`CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN` remain required for remote
Drizzle commands. This change does not invent or commit those credentials.

## Testing

1. Unit-test the redirect helper for all five exact paths, query strings,
   unrelated paths, and similarly prefixed subpaths.
2. Test that the five route files and generated route entries are absent.
3. Run the complete TypeScript test set, Biome check, locale check, and
   production build.
4. Against the running local server, verify every retired path returns HTTP
   301 with `Location: /` on the same origin.
5. Fetch the raw SSR HTML for `/` and `/challenge`, parse every JSON-LD script,
   and verify the expected schema types remain present.

## Commit Boundary

The route retirement, redirect helper, tests, local ignored `.env` update, and
generated route tree are verified together. Only tracked source and test files
are committed; `.env` remains local and ignored. Turnstile and server-issued
game sessions begin in a separate subsequent change.
